# Священный таймлайн

Расширение SillyTavern: одна история — много эпох. Разводит лорбуки, обличья персонажей и расширки
по времени и сшивает всё в одну Хронику.

Здесь только код. Дизайн, лор и данные живут в приватной репе данных (`docs/DESIGN.md` там),
сами лорбуки — в SillyTavern.

Статус: мост `st-sync` работает; ядро расширения — v0.8.2.

## Расширение (ядро, v0.9)

Ставится в SillyTavern по ссылке на эту репу: **Расширения → Install extension →**
`https://github.com/clarawill137/sacred-timeline` → Install, потом обновить страницу.
Обновлять — через `st-sync` (ниже: он сам тянет расширки из списка); руками — кнопкой обновления в строке
«Священный таймлайн» в Manage Extensions (не «Update all»: он обновит и пропатченные чужие расширения).

В списке расширений — блок «Священный таймлайн»: эпоха и дата чата, что срезано, переключатели.

Что умеет:
- узнаёт эпоху чата по Реестру мира — лорбуку, чьё имя кончается на «Реестр»
  (метка `chat_metadata.sacred_timeline.era` → чат в списке эпохи → группа эпохи → эпоха по умолчанию);
- **миры**: чат без эпохи, в котором нет ни одной личности мира (по карточкам обличий и именам), — чат чужого
  мира. Там книги этого мира (`books`, `ownBooks`, Хроника, Реестр) не уходят в промпт, расширки из
  `world.outside` выключены, `body[data-st-world="none"]`, снимок — с `world: null`;
- узнаёт дату сюжета: метка `sacred_timeline.date` → трекер RPG Companion → Horae; не выходит за рамки эпохи
  (последний месяц эпохи — её целиком: день внутри него остаётся днём);
- **дата «с этого места»** (0.9.8): `/era date=1961-03-15` (или «март 1961», или поле «Дата сюжета» в настройках) ставит
  дату сюжета от текущего сообщения — пока в следующих сообщениях не появится своя (трекер, Horae); `/era date=off`
  снимает метку. Так перескакивают через годы внутри одной эпохи. Метка без `dateAt` (поставленная руками) — жёсткая;
- **стык эпох** (0.9.8): месяц, которым эпоха кончается, — её финал, и он общий с тем, что начинается следом. Пока
  дата внутри него: человек, чья линия жизни кончается этим месяцем, ещё в мире; облик, который кончается им, ещё
  длится; фиксированная точка, датированная этим месяцем, — режиссёру «впереди», а не в «что было» (пока не `gc.played`); знание и
  `gc.public`, которые приходят ровно в нём, — ещё не знание. Дата ушла за конец эпохи (трекер или метка) — финал
  сыгран, всё это снимается. В следующей эпохе тот же месяц считается как обычно;
- **лорбуки по эпохе**: книги, которым Реестр задал эпохи, — только в них; записи с `gc.eras` — только в своих
  эпохах (`gc.inject` — выключенный срез, ядро включает его само); записи Хроники, начинающиеся позже даты
  сюжета, — вон;
- **книги эпохи**: книги из списка эпохи в Реестре (`lore`) ядро само подключает в чатах этой эпохи — без
  глобальных лорбуков в настройках ST. Только в чатах, отмеченных в Реестре; книгу, уже подключённую самой ST
  (глобально, у персонажа, у чата), не задваивает; книги, которой нет на сервере, — пишет в статусе. Дальше записи
  идут через тот же фильтр по эпохе, дате и знанию. Выключается вместе с «Лорбуки по эпохе чата»;
- **книги личностей** (одна на человека, подключена ко всем его карточкам): у записей метки времени. Состояние
  (`kind: "state"` с `to`) видно только внутри своего отрезка; часть эпохи (`gc.part`) без даты чата меряется началом
  эпохи — годы не смешиваются. Запись части, которая и позже правда, может жить дольше своей эпохи — просто `to`
  подальше (и пометка `gc.lift` — почему). На стыке эпох части чужой эпохи судятся строго (0.9.5): кончилась к
  началу этой эпохи (`to` ≤ её `from`) или начинается с её конца (`from` ≥ её `to`) — не видна, хотя месяц стыка
  общий и `to` включительный;
- **отрывки по дате внутри записи**: `⟦с 2018-04: …⟧` — кусок текста виден с этой даты, `⟦до 2020-06: …⟧` — по
  эту дату включительно, `⟦с 2016-04 по 2023-10: …⟧` — внутри отрезка (можно `from` / `until` / `to`; «с» — и
  латиницей). Пара `⟦с 2015-05: новое⟧⟦до 2015-04: старое⟧` — «было так, стало эдак». Одна запись на все годы: там,
  где отрывок виден, текст слово в слово как без скобок; где нет — отрывка нет, лишних пробелов тоже. Работает в
  промпте и в `visible()` для расширок; сама книга не меняется;
- **кто что знает**: тайна с картой знания (`gc.knows`) идёт в промпт только тому, чья сейчас очередь говорить
  и кто знает её на дату сюжета (в группе — по ходу каждого участника; «обрывки» — не знание; неопознанному
  говорящему тайн не даём); без карты знания — событие из личного времени персоны (`gc.personal`) позже её
  «сейчас» в эпохе отсекается;
- **персона по эпохе**: правки из Реестра (`personaPatches` эпохи) прямо в промпте — сама персона в ST не меняется;
- **аватар персоны по эпохе**: у обличья эпохи в Реестре может быть свой аватар (`persona` у среза — файл в
  User Avatars). Ядро заводит под него персону-двойника (то же имя; описание — базовое с правками эпохи, так что
  его видят и расширки, читающие персону напрямую; без привязок к персонажам),
  в отмеченных чатах эпохи переключает на неё и закрепляет за чатом; уходя в другие чаты — возвращает базовую.
  Чужие персоны не трогает. Нужен, чтобы расширки, берущие аватар персоны как реф для картинок, видели облик
  нужного времени. Выключается вместе с «Персона по эпохе чата»;
- **Хроника под дату** (вместо ★ХРОНОЛОГИИ там, где она не живёт): из Хроники мира — что было до даты сюжета и что
  из этого известно говорящему (мировые фиксированные точки и `public` — всем; `public` с датой — тайна до неё, дальше
  всем; личная история — участникам `who` и знающим `knows`, а если у тайны есть карта знания — только по ней: в сцене
  был — ещё не значит знает; рассказчику — всё несекретное; подсобытия тайного отрезка — тайна и сами; закончившиеся
  состояния не идут); далёкие отрезки — одной строкой. События своей эпохи позже её начала идут в «что было», только
  когда сыграны (`played`: `true` или дата сцены — тогда и судим по ней; или запись пришла из чата — `src.chat` /
  `src.stmb`): сводка не обгоняет ролку. Событие ровно в начало эпохи — завязка, оно уже было. И ближайшие фиксированные точки впереди — режиссёрской пометкой «не
  ломать, персонажи не знают». В промпт (IN_PROMPT) на каждой генерации, только в отмеченных чатах; выключается
  отдельно;
- **обрывки памяти** (0.9.5): если в карте знания у говорящего на дату отрезок `mode: "fragments"` (а не `knows`),
  к Хронике под дату добавляется «подтекст» — подсказки события `gc.hint` (строка или `{ id говорящего | "*": текст }`)
  без имён: тело, запах, слово, дежавю, без узнавания. Без подсказки обрывок не показывается (в заголовках имена).
  Страж получает строку «у кого в сцене обрывки — только подтекст»;
- **кто есть кто**: короткая шпаргалка на дату сюжета — в чат перед последним сообщением, от системы, на каждой
  генерации (в группе — на ходу каждого участника). Строки эпохи из Реестра (`who`, с `from`/`to` и `speaker`) и
  «нет в этом времени: …» — кого ядро убрало из Закулисья, с причиной (`gone` личности, иначе по датам смерти и
  рождения). Только в эпохах, у которых в Реестре есть `who`, и только в чатах, отмеченных в Реестре;
- **Закулисье**: кого в эпохе нет (умер, пыль, лёд, не родился) — закомментирует в составе (а когда сюжет дойдёт до
  его появления — вернёт строку, 0.9.8), уберёт их повестки
  и события за кадром; кого вернёшь руками — больше не тронет;
- **режимы расширок по эпохам**: в Реестре — каталог расширок (`gc.type: "ext"`: `id`, ключи промпта
  `prompts` — ключи `extension_prompts`, кнопки и панели `ui` — CSS-селекторы) и режимы у эпохи (`ext`:
  `{ id: режим }`). `off` — промпт расширки не уходит, кнопки спрятаны, а если в каталоге есть заслонка
  (`gate: { settings, key }` — главный выключатель в `extension_settings`), расширка видит его выключенным и в
  чатах эпохи ничего не делает; `quiet` — только промпт, `hidden` — только кнопки; другой режим ядро само не
  применяет, его читает расширка. Файл настроек не меняется: ключ глушится в момент сборки промпта (расширка
  пишет как обычно, ST читает пустое), заслонка отдаёт расширке `false`, а в сохранение настроек уходит настоящее
  значение. Ушла из эпохи — всё вернулось само. Только в чатах, отмеченных в Реестре;
- **память эпохи**: у эпохи в Реестре может быть свой меморибук (`memoryBook`) и флаг `bindMemory` — тогда в её
  каноничном чате (`canonChat`) ядро ставит меморибук книгой чата, и STMemoryBooks пишет память туда. Книгу чата,
  которую поставила ты сама, не перебивает: меняет только пустую или одну из книг эпохи (их ядро и так подключает
  само); книги, которой ещё нет на сервере, не ставит. Свежие записи STMB ядро размечает (`gc.kind: "memory"`):
  дата сцены (трекер/Horae у её последнего сообщения, иначе дата чата), эпоха, кто был в сцене — те и знают
  (`knows`), откуда (чат, сообщения). Размеченная память видна в своей эпохе и всех позже — как история: ядро само
  подключает меморибуки прошлых эпох и пропускает только то, что говорящий знает; назад во времени — никогда.
  Рассказчику (неопознанному говорящему) видна вся память своей эпохи;
- **списки персонажей в настройках расширок** (`views` в каталоге: `{ settings, key }`, строки «Имя = …» или
  «Имя | …»): тех, кого на дату нет в мире, расширка видит закомментированными; в сохранение настроек уходит
  настоящий список, пометки ядра снимаются сами. Вид `eras` (`{ settings, key, kind: "eras", eras: [...] }`): поле
  нужно только в этих эпохах — в остальных расширка видит пустое, а пустое из её настроек не затирает настоящее;
- **канон-конвейер** (0.9): Страж → память → Хронист → Ревизор → решение. В Хронику пишет только каноничный чат эпохи.
  - **Страж** — графа `canon` в Летописце Life (через `LifeBridge`, если Life стоит): после каждого поста его дешёвая
    модель получает строки «Канон» — дата сюжета, ближайшие фиксированные точки впереди, кого нет в этом времени, тайны
    среди тех, кто в сцене (кто знает, кто нет; «в сцене был, а не знает» — первыми; несыгранное своей эпохи — не
    тайна сцены) — и отвечает `ok`, `warn` (кто-то знает то, чего не может) или `break` (сломана фиксированная точка,
    в сцене тот, кого нет). Не `ok` — 🚩 под постом: что не так и как поправить, «✕ так задумано». Флажок привязан к
    свайпу и тексту поста;
  - **Хронист**: свежая память STMB каноничного чата (уже с датой и знанием) — подзаписью Хроники 🟡 «на проверке»
    (`gc.status: "review"`, ссылка на память `src.stmb`, у памяти — `gc.draft`). Если стоит Life — её модель Летописца
    переписывает подзапись по плану: что случилось, «По личностям», «Последствия для будущего». На проверке в сводку не идёт;
  - **Ревизор** — сильная модель по своему профилю Connection Manager (выбрать в настройках). Сверяет подзапись с
    постами-источником (ошибку Хрониста правит сам — правку видно, её можно откатить) и с каноном: фиксированные точки,
    события рядом по времени, кто где и что знает. В рамках — подзапись сразу в каноне; ролка противоречит канону —
    нексус 🚩 (что и с чем расходится, что ещё задето);
  - **нексус решаешь ты** — в настройках расширения и во вкладке «Сцена» Life: ✂ **Подрезать** — Ревизор переписывает
    посты ветки под хронологию, показывает «было → стало», применяется по кнопке (память этой сцены после — перегенерировать
    в STMB); ✓ **Вписать в таймлайн** — побеждает новое, задетое (записи Хроники, лорбуки, память, посты других эпох)
    списком в `gc.touched`; ⑂ **Своё** — пишешь словами, как разрулить, Ревизор переписывает подзапись по твоим словам.
- **Ход — кто ответит** (0.9.7, модуль `hod.js`): в групповом чате у поля ввода кнопка с силуэтами — панель участников
  группы с аватарками; тап по персонажу — он пишет ответ (как `/trigger`, только текст из поля ввода не стирается, а
  уходит твоим сообщением перед ответом). Пока кто-то пишет, тап ставит в очередь (номер на кнопке и на аватарке;
  повторный тап убирает, «стоп» отменяет очередь); черновик в поле ввода на время хода из очереди прячется и
  возвращается. Последний писавший обведён. С миром: кого нет в этом времени — бледнее и в конце; если у человека в
  группе несколько карточек (по годам), ярче та, что на дату сюжета (`people[имя].card`). Настройки — «Ход — кто
  ответит» в расширениях; там же галочка убрать из поля ввода чужие кнопки, которыми не пользуются.
    Без профиля Ревизора подзапись можно вписать руками. В историю других эпох идёт только каноничная память;
- `body[data-st-era]`, `body[data-st-year]`, `body[data-st-world]` — темы и CSS могут смотреть на эпоху и мир;
- `/era` — эпоха и дата чата; `/era date=…` — поставить дату сюжета с этого места, `/era date=off` — снять.

Лора в коде нет: всё берётся из Реестра на сервере.

### Для других расширений

```js
const cx = window.SacredTimeline?.context();   // null — чат вне мира или ядра нет
// {
//   v: 1,
//   world:   { id, name, chronicle, defaultEra },
//   era:     { id, label, from, to, status, memoryBook, lore: [книги эпохи] },
//   explicit: true,          // эпоха отмечена в Реестре (false — взята по умолчанию)
//   chatId, date: 'YYYY-MM-DD' | 'YYYY-MM' | null, dateSource,
//   speaker: { identity, slice, avatar } | null,    // кто сейчас говорит (в группе — на каждом ходу свой)
//   cast:    [{ identity, slice, name, card }],     // состав эпохи по обличьям
//   persona: { identity, slice, avatar } | null,    // обличье персоны в эпохе
//   people:  { [имя в чате]: { identity, slice, label, card } },  // участники чата и персона — для данных «по имени»
//   ext:     { [id расширки]: 'on' | 'off' | 'quiet' | 'hidden' | свой режим },
// }
window.SacredTimeline?.mode('my-ext');          // режим расширки здесь; вне эпох — 'on'
// записи лорбука, которые видно отсюда (дата сюжета, кто говорит, что знает) — если расширка сама читает книги:
const seen = await window.SacredTimeline?.visible(entries, 'Имя книги');

// Хронограф (лента эпох, как в Фойе): эпохи с чатами, составом и очередью канона + события Хроники (вид автора):
const map = await window.SacredTimeline?.chronograph();   // { world, span, eras: [...], events: [...] } | null
// span — рамки ленты [год, год]: из записи мира в Реестре (gc.span), иначе — по эпохам и событиям
await window.SacredTimeline?.enter('id эпохи');           // открыть её каноничный чат — дальше ядро переключит всё само
await window.SacredTimeline?.sliceAt('Имя', '2014-05');   // облик человека на дату: { identity, slice, label } | null

// снимок поменялся (чат, эпоха, дата, говорящий):
SillyTavern.getContext().eventSource.on('sacred-timeline:changed', cx => { /* … */ });
window.addEventListener('sacred-timeline:changed', e => { const cx = e.detail; /* … */ });
```

Личность (`identity`) — один человек сквозь все годы, обличье (`slice`) — он на отрезке времени (своя карточка
или персона). Хранить данные «по личности + обличью» — значит не путать годы и не видеть будущего: расширка, которая
держит что-то по имени персонажа (шкаф, вкусы, распорядок), берёт `context().people[имя].slice` и помечает им запись.

У одного человека бывает несколько карточек с одним и тем же именем — по карточке на эпоху. Искать карточку по имени
(`characters.find(x => x.name === имя)`) поэтому нельзя: попадётся первая по списку, из чужого года. Карточка, которой
человек представлен в этом чате, — `context().people[имя].card` (0.9.6); если в одной группе у него несколько карточек
(эпоха через годы), облик и карточка — по дате сюжета.

## st-sync — правки без переустановок

Claude правит лорбуки, пресеты и карточки прямо в файлах сервера через приватную репу `clarawill137/st-data`.
Синкаются только `worlds/`, `OpenAI Settings/`, `groups/`, PNG из `characters/` и аватарки персон из `User Avatars/`.
Из `settings.json` — только выжимка для чтения (`_export/settings-safe.json`: персоны, привязки лорбуков, теги).
Чаты: всегда уезжает только их список (`_export/chats-index.json`), сами чаты — лишь те, что Claude попросил
в `_request/chats.txt` (кладутся в `_chats/`). Чаты от Claude (`_out/`) ставятся только новыми файлами —
существующий чат мост не перезапишет никогда. Бэкапы и ключи API (`secrets.json`, токены расширений) не уезжают.

**Установка** (один раз, в Termius на сервере ST):

```
curl -fsSL https://raw.githubusercontent.com/clarawill137/sacred-timeline/main/tools/st-sync.sh -o /usr/local/bin/st-sync && chmod +x /usr/local/bin/st-sync && st-sync setup
```

Команда выдаст ключ → github.com/clarawill137/st-data → Settings → Deploy keys → Add deploy key →
вставить, галочка «Allow write access» → Add key. Потом ещё раз `st-sync setup`.

**Каждый раз:**

| Команда | Что делает |
|---|---|
| `st-sync` | снимок сервера → забрать правки Claude → показать список → применить → обнови страницу ST |
| `st-sync undo` | откатить последнее применение (свежие записи STMB остаются) |
| `st-sync status` | ждут ли правки |
| `st-sync update` | обновить сам st-sync |

Защита: битый JSON не применяется, конфликт со свежими изменениями на сервере — тоже (Claude сводит и шлёт заново),
пустая папка на сервере — стоп. Вся история в git — ничего не теряется насовсем.

Оборванный запуск (закрыли окно на вопросе «Применить?») следующий запуск замечает и применяет правки заново.
**Сторож откатов**: если после применения страницу ST не обновили и таверна сохранила поверх свою старую копию
лорбука, следующий `st-sync` скажет, какие записи откатились (и оставит пометку в истории репы) — сам не чинит.

Обновить сам скрипт — `st-sync update` (или та же команда `curl`, без `&& st-sync setup`).
