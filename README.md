# Священный таймлайн

Расширение SillyTavern: одна история — много эпох. Разводит лорбуки, обличья персонажей и расширки
по времени и сшивает всё в одну Хронику.

Здесь только код. Дизайн, лор и данные живут в приватной репе данных (`docs/DESIGN.md` там),
сами лорбуки — в SillyTavern.

Статус: мост `st-sync` работает; ядро расширения — v0.5.

## Расширение (ядро, v0.5)

Ставится в SillyTavern по ссылке на эту репу: **Расширения → Install extension →**
`https://github.com/clarawill137/sacred-timeline` → Install, потом обновить страницу.
Обновлять — кнопкой обновления в строке «Священный таймлайн» в Manage Extensions
(не «Update all»: он обновит и пропатченные чужие расширения).

В списке расширений — блок «Священный таймлайн»: эпоха и дата чата, что срезано, переключатели.

Что умеет:
- узнаёт эпоху чата по Реестру мира — лорбуку, чьё имя кончается на «Реестр»
  (метка `chat_metadata.sacred_timeline.era` → чат в списке эпохи → группа эпохи → эпоха по умолчанию);
- узнаёт дату сюжета: метка `sacred_timeline.date` → трекер RPG Companion → Horae; не выходит за рамки эпохи;
- **лорбуки по эпохе**: книги, которым Реестр задал эпохи, — только в них; записи с `gc.eras` — только в своих
  эпохах (`gc.inject` — выключенный срез, ядро включает его само); записи Хроники, начинающиеся позже даты
  сюжета, — вон;
- **книги эпохи**: книги из списка эпохи в Реестре (`lore`) ядро само подключает в чатах этой эпохи — без
  глобальных лорбуков в настройках ST. Только в чатах, отмеченных в Реестре; книгу, уже подключённую самой ST
  (глобально, у персонажа, у чата), не задваивает; книги, которой нет на сервере, — пишет в статусе. Дальше записи
  идут через тот же фильтр по эпохе, дате и знанию. Выключается вместе с «Лорбуки по эпохе чата»;
- **кто что знает**: тайна с картой знания (`gc.knows`) идёт в промпт только тому, чья сейчас очередь говорить
  и кто знает её на дату сюжета (в группе — по ходу каждого участника; «обрывки» — не знание; неопознанному
  говорящему тайн не даём); без карты знания — событие из личного времени персоны (`gc.personal`) позже её
  «сейчас» в эпохе отсекается;
- **персона по эпохе**: правки из Реестра (`personaPatches` эпохи) прямо в промпте — сама персона в ST не меняется;
- **кто есть кто**: короткая шпаргалка на дату сюжета — в чат перед последним сообщением, от системы, на каждой
  генерации (в группе — на ходу каждого участника). Строки эпохи из Реестра (`who`, с `from`/`to` и `speaker`) и
  «нет в этом времени: …» — кого ядро убрало из Закулисья, с причиной (`gone` личности, иначе по датам смерти и
  рождения). Только в эпохах, у которых в Реестре есть `who`, и только в чатах, отмеченных в Реестре;
- **Закулисье**: кого в эпохе нет (умер, пыль, лёд, не родился) — закомментирует в составе, уберёт их повестки
  и события за кадром; кого вернёшь руками — больше не тронет;
- `/era` — эпоха и дата чата; `window.SacredTimeline` — для других расширений.

Лора в коде нет: всё берётся из Реестра на сервере.

## st-sync — правки без переустановок

Claude правит лорбуки, пресеты и карточки прямо в файлах сервера через приватную репу `clarawill137/st-data`.
Синкаются только `worlds/`, `OpenAI Settings/`, `groups/` и PNG из `characters/`.
Из `settings.json` — только выжимка для чтения (`_export/settings-safe.json`: персоны, привязки лорбуков, теги).
Чаты: всегда уезжает только их список (`_export/chats-index.json`), сами чаты — лишь те, что Claude попросил
в `_request/chats.txt` (кладутся в `_chats/`). Чаты от Claude (`_out/`) ставятся только новыми файлами —
существующий чат мост не перезапишет никогда. Бэкапы и ключи API (`secrets.json`, токены расширений) не уезжают.

**Установка** (один раз, в Termius на сервере ST):

```
curl -fsSL https://raw.githubusercontent.com/clarawill137/sacred-timeline/main/tools/st-sync.sh -o /usr/local/bin/st-sync && chmod +x /usr/local/bin/st-sync && st-sync setup
```

Команда выдаст ключ → github.com/clarawill137/st-data → Settings → Deploy keys → Add deploy key →
вставить, галочка «Allow write access» → Add key. Потом ещё раз `st-sync setup`.

**Каждый раз:**

| Команда | Что делает |
|---|---|
| `st-sync` | снимок сервера → забрать правки Claude → показать список → применить → обнови страницу ST |
| `st-sync undo` | откатить последнее применение (свежие записи STMB остаются) |
| `st-sync status` | ждут ли правки |
| `st-sync update` | обновить сам st-sync |

Защита: битый JSON не применяется, конфликт со свежими изменениями на сервере — тоже (Claude сводит и шлёт заново),
пустая папка на сервере — стоп. Вся история в git — ничего не теряется насовсем.

Обновить сам скрипт — `st-sync update` (или та же команда `curl`, без `&& st-sync setup`).
